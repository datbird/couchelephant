{# ---------------- Backup and restore ---------------- Two ways to protect the same data, each with its own backup and its own restore. A live copy saves you from losing the machine; a snapshot saves you from a change you regret, because a live copy faithfully copies the mistake. #}

Export and import

Everything you decided, in one file. Your passes and their conditions, the recordings you booked, your channel artwork, your settings and your accounts.

Export

The guide is not in it. Programmes and airings rebuild from your Plex server in seconds, so a stale copy would be bigger and wrong.

The Plex token, the Cloudflare AUD and the backing-store passwords. Off by default: they are credentials, and an export is a file that ends up in an email.

Import

Read an export back in. It says what is in the file before anything is written.

Merging writes everything in the file and leaves anything else here alone. Replacing removes what the file does not carry, so the result is exactly what was exported.

Snapshot backups

A copy of a moment, written on a schedule and kept for as long as you say. This is what saves you from a change you regret.

Restore from an archive

Read the list from any folder, including one written by an install you no longer have.

Backing store

Keep a live copy of your decisions in another database, both ways. Change something here and it appears there. Rebuild this machine and it comes back.

The guide is never copied. It is an output, not data.

Where to keep it

Minutes. 0 does it only when you press the button.

Now

Restoring pulls everything down and writes nothing back, so restoring onto an empty machine cannot erase the copy you are restoring from.
